# Architecture Decisions

## Layered monolith (no microservices)
**What:** Single Spring Boot application serving all domains — auth, products, users, files.
**Why:** Single-vendor store with one admin and a predictable traffic profile. Microservices overhead would outweigh benefits at this scale.
**Consequence:** All business logic lives in `service/`. Keep domains separated inside this monolith — do not create cross-service dependencies.

## Flyway migrations, never modify existing files
**What:** All schema changes go in new `V<n>__description.sql` files. Existing migration files are immutable.
**Why:** Flyway checksums existing files and will refuse to start if they change. Any modification breaks all deployments.
**Consequence:** Mistakes in a migration require a new corrective migration. The current high-water mark is V26.

## Spanish-only content, no translation layer
**What:** All user-facing strings (category names, material names, attribute names, attribute values) are stored directly in Spanish in each entity column.
**Why:** The store is Mexico-only (MXN, Spanish). A translation subsystem was built (V9–V12) and removed in V21 because it added complexity with no benefit for a monolingual store.
**Consequence:** Do not reintroduce `languages`/`translations` tables. Add columns to entities if new localizable content is needed. `attributes.attribute_type` stays as an internal enum code (COLOR/SIZE/CARAT); only `attributes.name` is Spanish.

## Soft delete pattern
**What:** Deletable entities (Category, Brand, Material, Product) have a `deleted_at` nullable timestamp. Setting it marks the record as deleted; setting it to null restores it.
**Why:** Allows restore-without-data-loss and avoids FK constraint errors when deleted records are still referenced by orders or other entities.
**Consequence:** Every query that should exclude deleted records must explicitly filter `WHERE deleted_at IS NULL`. Repository methods named `findAllNotDeleted` and `searchByName` already do this for categories.

## Synchronous thumbnail generation
**What:** After any image upload, `ThumbnailService.generateThumbnails()` blocks the HTTP request thread to produce 200×200 and 400×400 variants in-process via Thumbnailator.
**Why:** Simplest approach at current scale. No async queue, no worker process, no S3 — files live on disk.
**Consequence:** Upload requests are slower than they would be with async processing. If file uploads become slow under load, this is the first thing to make async. Do not introduce background threads for this without discussing it first.

## LocalStorageService as the only storage implementation
**What:** `StorageService` interface has one implementation: `LocalStorageService`, which writes to `FILE_DIRECTORY` on disk. Files are served by Spring via `WebConfig` static handler at `/api/v1/file/**`.
**Why:** No S3 or CDN budget at this stage. The interface exists to make it swappable later.
**Consequence:** `FILE_DIRECTORY` must be the same path on the host and inside the Docker container (mapped volume). Changing to S3 later requires implementing `StorageService` and updating `WebConfig`.

## UUID primary key for products
**What:** `products.product_id` is UUID (generated by PostgreSQL `uuid_generate_v4()`), while other entity PKs are BIGSERIAL.
**Why:** Products may be referenced from external systems (order management, frontend URLs) where sequential IDs would be guessable/scrapable.
**Consequence:** Product IDs in Java are `UUID` type, not `Long`. Repository lookups use `findById(UUID)`. Do not mix UUID and Long for product-related path variables.

## Messages via MessageService, never hardcoded strings
**What:** All user-facing error and success messages come from `messages_es.properties` via `MessageService.getMessage(key, locale)`. Always use `LocaleUtils.getDefaultLocale()` (returns `Locale("es")`).
**Why:** Centralizes all copy in one file, makes future locale additions trivial, prevents Spanish strings scattered through Java code.
**Consequence:** When adding any new error or success scenario, add the key to `messages_es.properties` (and `messages.properties` for the English fallback). Never pass a raw Spanish string to `ApiServiceException` or `DefaultApiResponse`.

## Login lockout enforced in AuthService
**What:** 5 failed login attempts within the last 1 hour triggers HTTP 423. Attempts are logged in `login_attempts` table.
**Why:** Brute-force protection. The threshold is stored in the service, not configurable via env var.
**Consequence:** Tests that exercise login failure paths need to account for this — mock `LoginAttemptRepository` appropriately.
